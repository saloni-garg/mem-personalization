Write Less, Remember Better: Verified Write Gates for Long-Term Personalization Memory

Saloni Garg

Working paper, November 2026

Abstract

Long-term memory is now a standard component of personal AI agents, and when personalization goes wrong the failure is usually blamed on retrieval. We argue the failure starts earlier, at the write. Memory stores in production accumulate entries that the source conversation does not support: preferences the user never stated, facts the assistant inferred and then recorded as fact, and stale versions of facts the user later corrected. Once written, an unsupported memory is retrieved faithfully and acted on in later sessions, so a single bad write compounds. Current benchmarks for long-term memory measure whether stored content can be retrieved and used to answer questions; they do not measure whether the stored content should have been stored. We introduce a write-side evaluation for personalization memory covering junk rate, duplication, coverage, and false-preference adoption, and we evaluate a simple intervention: a write gate that stores a candidate memory only when it is verified against a verbatim quote from the user's own words in the source conversation. In a pre-registered experiment on controlled multi-session streams with planted facts, contradictions, and injected false preferences (20 personas, 6 sessions each), the gated store's junk rate was 0.167 against 0.286 for ungated extraction, false-preference adoption fell from 1.000 to 0.000, and downstream task score rose from 0.833 to 1.000, with coverage of true facts at 1.000 for both systems. The gate's junk reduction did not reach our pre-registered 10x threshold: its residual junk is dominated by superseded facts, a staleness failure that a provenance check cannot catch. The supported claim is narrower and, we think, more useful: verifying writes eliminates fabricated memories at no measured cost to coverage or task performance, and the remaining write-side problem is freshness, not fabrication.

1. Introduction

Personal agents now carry memory across sessions, and personalization is the product promise: the agent should learn what the user likes, where they live, how they work, and use that knowledge later without being told again. When this goes wrong, the standard diagnosis is retrieval: the right memory was stored but not found, or the wrong one was ranked first. Retrieval quality matters, but it assumes the store itself is sound.

The store is rarely measured. Extraction pipelines read a conversation and write down what they take to be durable facts and preferences. Nothing in a typical pipeline checks a written entry against what the user actually said. Assistant inferences get recorded in the same format as user statements. A preference mentioned once in passing, or invented in an assistant's summary of a session, is written with the same standing as something the user stated plainly. When the user later corrects a fact, the old version often stays in the store next to the new one. Over months of sessions, a store fills with entries of mixed standing, and every downstream read treats them alike.

A wrong memory is worse than no memory. A missing fact costs a clarifying question. A fabricated preference is retrieved with confidence and acted on, and because the agent acts on it, the resulting conversation can generate further writes that reinforce it. The failure compounds at the write, not at the read.

This paper measures the write side and tests one intervention. Our contributions are:

  • A write-side evaluation protocol for personalization memory: junk rate, duplication rate, coverage of planted true facts, false-preference adoption, and downstream task score, computed against planted ground truth.
  • A verified write gate: a candidate memory is stored only if it carries a supporting quote that appears verbatim in the user's own turns of the source conversation. Unverifiable candidates are dropped, not stored pending.
  • A pre-registered experiment comparing ungated extraction, the gated store, and a no-memory control on identical streams, with hypotheses, margins, and falsification conditions frozen before any system ran.

2. Related work

Deployed memory systems such as Mem0, Zep, and Letta (MemGPT) are extraction-first: a model reads conversation and writes structured memories, and the engineering effort goes into storage, retrieval, and ranking. Write verification against the source text is not part of these designs. Benchmarks for long-term memory, including LoCoMo and LongMemEval, evaluate question answering and retrieval over long conversational histories; the correctness of what a system chooses to write is out of their scope. Our work is complementary: we keep retrieval fixed and vary only what is allowed into the store. The gate itself is a verifier, of the kind used to check model outputs and rewards, applied instead to memory writes at the moment they are made.

3. The verified write gate

The extraction step is unchanged. Given a session, an extractor model proposes candidate memories: short statements of fact or preference that a personalization system would want to keep. Each candidate must carry a supporting quote: a span of text the extractor claims the user said.

The gate applies one rule. A candidate is stored only if its supporting quote appears verbatim in the user's own turns of the source conversation. Quotes attributed to the assistant, paraphrases, and quotes that do not appear at all are rejected, and the candidate is dropped. Stored entries keep their quote and a pointer to the session they came from, so any entry in the store can be traced to the exact user statement that supports it. When a later session updates a fact, the store records a supersede link from the old entry to the new one rather than silently overwriting.

The rule is deliberately narrow. Verbatim matching is the weakest form of verification that still binds a write to evidence: it cannot judge whether a true statement is worth keeping, and it cannot detect that a once-true fact has gone stale. Section 6 shows both limits in the results. What it does bind is provenance: nothing enters the store that the user did not, at some point, actually say.

4. Evaluation protocol

4.1 Streams

We generate synthetic multi-session conversation streams with planted ground truth. Each persona has a set of true facts stated verbatim by the user across sessions, one fact that is later contradicted and replaced by an updated version, and one false preference that the user never states: it appears only inside an assistant's summary of a session, the channel through which fabricated preferences enter real stores. All streams for a run are generated in full, deterministically from a fixed seed, before any system runs on them. The main run uses 20 personas with 6 sessions each (seed 20261119).

4.2 Metrics

All metrics are computed per persona against planted ground truth, then averaged.

  • Junk rate. The share of stored entries not supported by a verbatim user statement: entries matching no planted fact, entries for the injected false preference, and entries for the superseded version of a contradicted fact.
  • Duplication rate. The share of stored entries that repeat the normalized content of an earlier entry for the same persona.
  • Coverage. The share of planted true facts, counting a contradicted fact once by its current version, that appear in the store in their current form.
  • False-preference adoption. On probe tasks built around the injected preference, the share of answers that act on it. Acting on the false preference is scored wrong by construction.
  • Task score. The share of all probe tasks (true-fact questions plus false-preference probes) answered correctly. True-fact questions are correct only when the answer uses the current version of a contradicted fact.

Because stored entries are free text, scoring needs a correspondence rule between an entry and a planted fact. We use the entry's attached quote: an entry corresponds to the planted fact whose statement the quote matches. This rule was fixed in the project's deviation log before the main run, after harness validation showed that matching on entry text instead would measure the extractor's phrasing rather than memory behavior.

4.3 Pre-registered hypotheses

Hypotheses, margins, and falsification conditions were frozen in a written pre-registration before the main run:

  • H1. The gated store's junk rate is at least 10x lower than the ungated store's.
  • H2. The gated system's task score is no worse than the ungated system's, within a margin of 5 percentage points.
  • H3. The injected false preference propagates in the ungated store (it is stored and acted on) and does not enter the gated store at all.

Comparisons are paired by persona. We report mean paired differences with bootstrap 95% confidence intervals (10,000 resamples, alpha 0.05).

5. Experiments

Three systems see identical streams. Ungated extraction stores every candidate the extractor proposes. Gated runs the same extractor and stores only candidates that pass the write gate. No-memory stores nothing and answers probes from the current session alone, as a control. Extraction and probe answering use one base model, Qwen2.5-32B-Instruct, for all systems. The main run was executed once, at the frozen size, under the frozen protocol.

6.1 Readout against the frozen hypotheses

H1 is falsified. The junk-rate ratio is 0.286 / 0.167, about 1.71x, well below the pre-registered 10x threshold. The gate removed on average one entry per persona, the fabricated one, and what remains in the gated store is instructive: the residual gated junk is the superseded version of the contradicted fact. That entry was supported by a verbatim user statement when it was written; it became junk later, when the user replaced the fact. A provenance gate cannot catch staleness, because the quote is genuine. The gate solves fabrication, not freshness.

H2 is supported. The gated system's task score is higher, not merely within the margin: 1.000 against 0.833, a paired difference of +0.167 against a non-inferiority margin of -0.05. Storing less did not hurt downstream performance on these tasks; it helped, because the gated store never acts on the false preference and always holds the current version of each fact in usable form.

H3 is supported. The injected false preference entered the ungated store for every persona and was acted on in every probe (adoption 1.000). It never entered the gated store: the only text supporting it is an assistant summary, and the gate accepts quotes from the user's turns only. Adoption in the gated system is 0.000.

The no-memory control scores 0.167 on the task suite, which confirms the probes actually depend on cross-session memory rather than on what can be answered from the current session alone.

7. Discussion

The results separate two write-side failure modes that are usually lumped together as bad memory. Fabrication, entries the user never supported, is stopped completely by a check so simple it is easy to overlook: require the quote, and require it to be the user's. Freshness, entries that were true and stopped being true, is untouched by that check and needs a different mechanism: supersede handling at write time and, where a store already exists, retirement of entries whose facts have been replaced. The gate's provenance records make the second problem easier to attack, since every entry knows which statement supports it and which entry replaced it, but the gate alone does not solve it.

There is also a training implication. Long-horizon agents are increasingly trained and evaluated against their own memory stores. A store contaminated at the write teaches the contamination: trajectories that act on fabricated preferences look, to a reward signal that trusts the store, like good personalization. Verifying writes is a cheap integrity check on that loop, applied before the data exists rather than after the behavior is learned.

8. Limitations

  • The streams are synthetic and constructed. Personas share a common structure, and the per-persona paired differences came out identical across personas, so the bootstrap confidence intervals are zero-width and carry no information about variability. The point estimates are exact for these streams; their generality is untested.
  • The experiment uses one base model (Qwen2.5-32B-Instruct) and one gate design (verbatim quote matching). Paraphrase-tolerant verification, and extractors that phrase candidates differently, may behave differently.
  • Junk labels come from planted ground truth, not from human judgment of real stores. The protocol measures what it plants.
  • The scale is small: 20 personas, 6 sessions each, one contradiction and one injected preference per persona.
  • The author built one of the systems compared (the gate is the write path of the Memline memory layer). The extractor, streams, and scoring are shared across systems, and the hypotheses and falsification conditions were frozen before the run, but the conflict is stated plainly.
